# Figma 设计规范 — 面向 AI 还原

> 适用对象：使用 `figma-android-mcp` 做 Android（Compose / View）还原的设计团队。
> 核心原理一句话：**AI 读的是设计稿的结构化数据，不是像素**。同一张图，画法规范与否，决定 AI 拿到的是"语义清晰的布局描述"还是"一堆散点坐标"。本规范的每一条都对应Figma MCP的一个具体解析能力。

---

## 1. 画板与密度（★★★★★）

- **画板宽度用 1× 基准**：360 或 375（≤480 判定为 1×）。Figma MCP按画板宽度自动推断设计密度做 dp/sp 换算：≤480 → 1×，481~900 → 2×，>900 → 3×。
- 全团队**统一一种基准**，不要同一项目里 375 和 750 混用——切换密度判定虽然自动，但混用会让同一组件在不同稿子里产出不同的 dp 值。

## 2. Auto Layout：能用就用，这是单条收益最大的规范（★★★★★）

Figma MCP对 Auto Layout 容器**直接输出** Column/Row、间距、对齐、padding——零猜测、零损耗。没有 Auto Layout 的容器只能走"位置推断"兜底链：先尝试从坐标推断行列，推不出再给锚点和分区建议，最后退化为绝对坐标。**每往下退一级，还原质量降一档。**

- 列表、表单、卡片内部、按钮组——一切有排列规律的内容都套 Auto Layout。
- 间距用 Auto Layout 的 spacing/padding 表达，**不要用空 Frame 或隐形矩形占位撑间距**。
- 要撑满直接父容器的子元素用 **Fill container**，不要手拉到 343 之类的"刚好"宽度——固定值只能靠 Figma MCP 猜意图，Fill 是明示。
- 该跟随内容的用 Hug contents。

## 3. 命名规范（★★★★）

Figma MCP会解析图层名做语义判定，命名不是装饰：

| 对象 | 重要程度 | 规范 | Figma MCP用途 |
|------|---------|------|-----------|
| 页面帧 | ★★★★★ | `页面名-状态名`，如 `订单详情-订单被拒` | SECTION 多状态分组按 `-`/`_`/`·`/`/` 分隔符解析页面与状态，命名错 = 分组错 |
| 弹窗帧 | ★★★★★ | 名称含 `弹窗`/`dialog`/`modal`/`sheet`，如 `信息选择-通用弹窗` | 弹窗识别的强信号（遮罩不透明时是必要信号），识别失败 = 背景页被重复还原 |
| ❌ 禁止 | ★★★★★ | 整页 `Frame 427`、`Group 12` | 所有命名信号失效，只剩视觉启发式兜底——违反代价最高 |
| toast 图层 | ★★★★ | 名称含 `toast`/`提示`/`snackbar` | toast 识别，命中即高置信度；无命名时仅靠视觉特征兜底，要求苛刻 |
| 组件 | ★★★ | 语义名：`输入框`、`Dropdown`，变体属性用 `state`/`type` | 组件状态映射，语义名直接成为代码里的状态枚举名 |
| 普通图层 | ★★ | 命名尽量见名知意：`头像`、`VIP角标`、`提交按钮` | 进入 AI 上下文，影响生成代码的可读性，不影响成败 |

## 4. 散点与重叠布局（★★★）

实在无法 Auto Layout 的自由布局（头像叠角标、活动页装饰），Figma MCP有锚点推断和附着检测兜底，但以下画法能让兜底更准：

- 自由布局里的元素位置要"站队"：**要么贴边（带明确边距），要么居中**。贴右 30dp 的元素，Figma MCP 输出"距右 30dp"锚点，换任何屏宽都贴右；画在既不贴边也不居中的位置，推断出的锚点和绝对坐标一样无意义，换屏宽必错位。
- 角标、徽章直接压在宿主（头像）上画，重叠关系会被识别为附着，AI 会把它们嵌套实现。
- 大面积纯装饰散点（满天星、气泡）：**建议整组打组并加 Export 标记**，作为一张背景图输出——逐个还原十几个装饰矢量是错误的努力方向。
- 也可以给元素设置 Figma **Constraints**（右锚/居中/拉伸）——显式约束优先于一切自动推断。

## 5. 切图与图标（★★★★）

- 需要作为资源交付的图（插画、复杂图标、品牌图）：**加 Export Settings 标记**。Figma MCP把 export 标记视为"设计师签发的资源清单"，与自动检测的候选分开处理。
- 命名即文件名：`icon_back`、`illus_hero`，会成为 `mipmap-*/` 下的资源名。
- 多密度（xhdpi/xxhdpi）下载是自动的，设计师无需切多套。

## 6. 多页面的组织（★★★）

多页面组织有两个维度，互补不冲突：

### 维度一：同一页面、多个状态（按页面分组）

- 同一页面的多个状态（空态/加载/正常/错误）放进**一个 SECTION**，每帧按 `页面名-状态名` 命名。
- AI 调用 `get_figma_section` 时会自动分组页面与状态、区分全页帧与弹窗帧，逐状态生成代码。
- 不属于任何页面的说明性内容（流程图、标注、走查记录）**放在 SECTION 外**，避免被当成页面状态。

### 维度二：同一功能、多个页面（按功能分组）

同一个功能模块往往跨越多个页面，比如"登录注册"功能的完整流程是 `登录页 → 注册页 → 忘记密码 → 短信验证`。把这些功能相关的页面放进**同一个 SECTION**，能让 AI 一次性拿到完整的功能上下文——页面间的跳转关系、数据流转、共享组件都能被更准确地还原，而不是把每个页面当孤岛处理。

- 功能内聚的页面放在一个 SECTION 里，SECTION 名用功能命名（如 `登录注册`、`订单流程`、`个人设置`）。
- 页面帧名保留 `页面名-状态名` 格式，`get_figma_section` 的按帧名分组逻辑不受影响。
- 与维度一的关系：先按功能分 SECTION，再在每个 SECTION 内按页面+状态组织帧——两个维度正交叠加。

## 7. 浮层画法（toast / 弹窗）（★★★★）

Figma MCP会识别静态稿里的瞬态 UI 并指导 AI 实现为事件触发（Toast/Snackbar/Dialog/BottomSheet），但识别质量取决于画法：

- **toast**：深色胶囊、水平居中、放在图层列表**最顶层**（z 最上）。配合命名（见命名规范表）= 高置信度。
- **弹窗遮罩（scrim）**：用**半透明深色矩形**（如 `#000000 40%`）盖满整帧——半透明本身就是决定性信号。如果用不透明深灰模拟，帧名必须含"弹窗"等关键词，否则会被当成深色背景保留。
- **弹窗背景放页面副本是允许的**（用来标记弹在哪个页面上）——Figma MCP会自动剥离遮罩之下的内容，不会重复还原。但背景副本应是**完整页面的副本**，不要在副本上又叠新增内容。
- 关闭按钮等悬浮在遮罩之上、弹窗体之外的元素，保持 z-order 在遮罩之上即可，会被正确保留。

## 8. 组件与状态：用 Variants，不要画"状态枚举帧"（★★★★★）

❌ 反例：单独画一帧，从上到下排"未填写 / 输入中 / 已填写 / 错误"四个输入框加文字标注。这对人类是规范，对 AI 是"一页摆了四个输入框的奇怪页面"。

✅ 正确做法：

- 输入框做成 **Component Set**，加 Variant 属性 `state`，值用语义名：`empty / focused / filled / error`（不要"变体2"）。Figma MCP会输出完整的变体选项列表，AI 直接映射成 `sealed class` / enum 状态参数。
- 错误提示文案、红描边放进 `error` 变体内部，不要散落在组件外。
- 按钮同理：`type: primary / secondary / disabled`。
- 页面里用**实例（Instance）**，只覆盖需要变的内容（占位文案、图标）。Figma MCP已支持覆盖值提取——AI 能看到"五个下拉框是同一组件，各自只有文案不同"，于是产出一个共享组件 + 五处传参，而不是五份重复代码。
- 可替换图标用 **Instance Swap 属性**，不要解组（detach）后手改。
- **永远不要 detach 实例**——detach 之后组件关系消失，AI 只能当普通图层逐个还原。
